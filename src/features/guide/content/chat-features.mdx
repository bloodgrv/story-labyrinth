# Chat Features

A few things that apply across every AI chat window — World-Building, Editor, Outline, Research, Notes, and Brainstorm alike: which model a chat talks to, what context gets sent alongside your message, how much of that context you're using, and a way to redirect off-topic questions without derailing the conversation.

---

## 1. The icon rail

Every chat host except the Editor (World-Building, Outline, Notes, Research, Brainstorm) shares the same icon rail on the right edge — a collapsible column of buttons, each opening the relevant panel as a modal sheet rather than cluttering the composer area permanently:

| Icon | Panel | What's there |
| --- | --- | --- |
| **Chats** | Non-modal docked column (not a sheet) | Your chat list for this desk — collapsed by default |
| **Approvals** | Modal, badge shows pending count | Codex proposals and Chat Shuttle items awaiting review, bundled together |
| **Context** | Modal, chip shows which toggles are armed | The Notes/Outline/Memory/Lorebook/Guide/auto-insert/auto-accept toggles (§3 below) |
| **Story Context** | Modal (Outline/WB only) | The older manual chapter/lorebook-entry picker — Include Full Context, or hand-pick specific summaries/entries/chapter text |
| **Playbook** | Modal | Guided Setup — style dropdown + "Guided setup" button, described in each desk's own guide page |

Click the collapse chevron at the bottom of the rail to shrink it to icon-only width. The Editor chat uses its own equivalent rail with the same shape — see the Advanced Guide's "editor tool rail" section for its full button list (it adds a few chapter-specific ones like Tags and Scanner).

## 2. Cloud | Local Model Routing

Every chat has a **Cloud** | **Local** pill at the top, next to the model dropdown. Switching modes filters the model list to just that provider group. Settings → Providers & keys has a **preferred mode** default, so a brand-new chat always starts with a real model selected instead of coming up modelless.

To edit a chat's system prompt, use the **⋯** menu next to the model control → **Edit system prompt**.

## 3. Context & Memory Toggles

Opt-in toggles live in the **Context** rail panel: Notes, Outline, Project Memory, Lorebook, Story Timeline, **Include Guide** (lets the chat answer questions about how to use the app itself), plus per-host toggles like auto-insert prose or auto-accept Codex where applicable. All default off. The rail icon shows a small chip listing which ones are armed (e.g. "Notes · Memory") so you can tell at a glance without opening the panel.

## 4. Per-message actions

Hover any message to reveal a small action bar beneath it:

| Action | Where |
| --- | --- |
| **Copy** | Every message |
| **Edit** | Every message — revise it in place |
| **Regenerate** | Assistant messages — re-run the model for a new reply |
| **Resend** | User messages — resend as-is |
| **Delete** | Every message |
| **Branch from here** | Every message — forks the conversation from this point into a new chat, leaving the original untouched |
| **Save as note** | Where the host supports it — captures the message straight into your Notes |

## 5. Context / Token Meter

A composer chip shows an estimated size of everything that would be sent with your next message — e.g. *"12.3k / 32k tokens (est.) · 62% left"* — with a small progress bar. It's always shown for **Local** models (since local context windows are usually the tightest constraint); for other providers it only appears once a real usage count is known from an earlier reply this session.

Click the chip to expand a **Context breakdown (est.)** popover — the same context assembly the chat actually uses, broken down by source (system prompt, anchor entry, project memory, notes, etc.) with a **Total** row at the bottom.

> [!TIP]
> For **Local** models, Settings → Local lets you set a context-window override and turn on a soft warning that asks for confirmation before sending once you're near the limit. It's off by default and never blocks a send outright — it just asks first.

## 6. Chat Shuttle

If you ask a World-Building, Editor, or Outline chat something that's really a real-world fact lookup (historical details, tradecraft, "what would people actually use for X") rather than a craft/continuity question, the model won't try to answer it out of its own knowledge — it proposes shuttling the question to the **Research** desk instead. A card appears right in the chat with the question and a short scene crumb, and three actions:

- **Open** — jumps to (or creates) your story's Research chat, pre-filled with the question
- **Answer here** — seeds the *current* chat's composer with the question instead, if you'd rather just answer it yourself without switching tools
- **Mark done** — dismisses the card once you've handled it

Nothing is ever sent automatically — every shuttle is something you choose to open. Active and done shuttles for a chat live in the **Approvals** rail panel (§1), alongside any Codex proposals — not a separate sidebar section. If you use Research's own **"Send brief to origin"** option, the brief comes back into that same panel.

## 7. Troubleshooting

| Problem                                       | What's happening                                                                     |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------ |
| A chat has no model selected                   | Set a preferred Cloud/Local mode in Settings → Providers & keys so new chats default correctly |
| Notes/Outline/Memory toggles seem to have disappeared | They live in the **Context** rail icon (§1/§3) — click it to open the panel, or check the summary chip on the icon itself |
| Token meter chip isn't showing                 | It's always on for Local models; for other providers it only appears after the first reply of the session reports real usage |
| A shuttle question just sits there             | Shuttles are never auto-opened or auto-answered — open **Approvals** and click **Open** or **Answer here** yourself |
| I can't find the per-message action bar        | It only appears on hover, and never while that message is mid-stream |

---

Model routing preference, the Context & memory disclosure state, and soft-warn settings are all stored locally on your device.
